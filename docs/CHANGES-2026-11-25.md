This change set:
- gets CI passing;
- closes three security and privacy holes;
- fixes the bugs found by driving every web-UI feature end to end with
  [`playwright-cli`](https://github.com/microsoft/playwright-cli) against

## 2. Security and privacy

### Resumes were uploaded to a third party by default

The README promised "your resume never leaves your machine". But
`[latex_api] enabled` defaulted to `true`, so every tailored resume and cover
letter was POSTed to the public `latex.ytotech.com`.

- Remote LaTeX compilation is now **opt-in**:
  - `enabled` defaults to `false`.
  - `render.tex_to_pdf` fails closed when `JOBAPPLY_LATEX_API_DISABLE` is
    unset.
  - `jobapply init` asks before enabling it.
- README, `jobapply.toml.example` and the config-writer comments are updated.

> **Upgrade note:** users who relied on the remote service need
> `[latex_api] enabled = true` in `jobapply.toml`, or a local `tectonic` /
> `pdflatex`. Markdown PDFs are always produced either way.

### The local web API could be reached by any website

`jobapply ui` had no Host check and no CSRF protection. A malicious page could
use DNS rebinding to read `/api/profile`, start paid `/api/run` jobs, or
overwrite `.tex` files.

- `TrustedHostMiddleware` only accepts `127.0.0.1` / `localhost`.
- POST, PUT and DELETE under `/api/` require an `X-JobApply-Client` header.
  The request's `Origin` must also be the app itself or the Vite dev server.
  The frontend sends the header automatically.
- `--host 0.0.0.0` turns off the Host check and prints a warning, because the
  API has no login.

### A LaTeX file edited in the browser could read local files

Verified before the fix: `\input{/path/to/secret}` embedded the file's
contents in the PDF. `pdflatex` now runs with:
- `-no-shell-escape`;
- kpathsea "paranoid" mode (`openin_any=p`, `openout_any=p`);
- `TEXMFOUTPUT` set to the job directory.

A real-engine test covers it.

## 3. Bugs found in end-to-end UI testing

| Area | Problem | Fix |
|---|---|---|
| Setup | `jobapply init` failed for every new Gemini user: `gemini-2.0-flash` is retired (404) | Default is now `gemini-flash-latest` (alias, won't go stale). Anthropic default `claude-3-5-haiku-latest` → `claude-haiku-5-5` |
| Search | Location "Remote" returned on-site jobs in Stockholm, London and NYC | "Remote" / "Anywhere" maps to the remote filter. Rows JobSpy doesn't flag as remote are dropped, because Indeed ignores `is_remote` when `hours_old` is set and LinkedIn ignores it always |
| Search | Missing fields showed as the literal text `"nan"` (company, URLs, description) | Pandas NaN / NA / NaT are mapped to empty |
| Search | Posting dates were always empty (code read a non-existent `date` column) | Reads `date_posted` |
| History | "5h ago" for a search that just ran: naive UTC timestamps were parsed as local time | The frontend treats offset-less timestamps as UTC |
| Batch tailor | Cancel marked the task "cancelled" instantly while the in-flight job kept running, so its card stayed "Pending" | The task stays `running` ("Cancelling…") until the worker stops, then becomes `cancelled`. The UI refreshes and picks up the finished job |
| LaTeX editor | Compile errors only said "probably a syntax error" | Shows the first TeX error with its line number, e.g. `Line 1: Undefined control sequence. (near: \foo)`, plus a count of the knock-on errors |
| PDFs | `.aux` / `.log` / `.out` files piled up in job folders | Removed after a successful local build |
| Cover letter | Header read "LinkedIn: link / GitHub: link", which is useless once printed | Shows the handle, e.g. `LinkedIn: alex-rivera-demo` |
| Email | Pre-filled subject kept "Platform Engineer - &lt;your name&gt;" | Name placeholders are filled from the profile |

### UX and accessibility

- The **Search** button is disabled with "Searching…" while a search runs,
  so a double-click can't start duplicate scrapes.
- The **search form remembers its inputs** across navigation and reloads
  (stored in `localStorage`).
- The **tailor and email dialogs** have `role="dialog"` and `aria-modal`.
  Focus moves into them and stays there, and Escape closes them (new
  `useDialog` hook).
- The email dialog notes that mail links can't attach the PDFs.

## 5. Known issues, not addressed here

- **LLM output makes up claims.** Generated cover letters and emails added
  things not in the profile ("mentoring team members", "on-call rotations",
  "hundreds of daily users" for 300 support agents). Recommended next step:
  check tailored text against `profile.json` before rendering.
- **Remote searches can return fewer results than requested**, since
  non-remote rows are now dropped after scraping.
- **Tectonic was not tested** (it wasn't installed in the test environment).
  The new sandboxing applies to `pdflatex` only.
- **Minor UI items:**
  - the resume/cover toolbar wraps awkwardly on narrow screens;
  - Ollama is listed as available even when no Ollama server is running.
